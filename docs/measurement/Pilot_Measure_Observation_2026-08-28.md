## 3. What the coding shows

### 3.1 A third of observed work has no task in the register

Approximately **36 of the \~98 coded minutes** fall outside the current 31-task register. The register covers the transactional purchasing flow well but does not represent the communication and exception work surrounding it.

Four recurring activity types have no home:

| Provisional activity type Episodes Approx. minutes       |                |     |
| -------------------------------------------------------- | -------------- | --- |
| Requester clarification of incomplete/ambiguous requests | OBS-02, OBS-06 | ≈13 |
| PO aftercare following colleague questions               | OBS-13, OBS-16 | ≈11 |
| Obtaining technical drawings / specifications            | OBS-14/15 (×3) | ≈15 |
| Order-status tracing / expediting                        | OBS-17         | ≈2  |

These are provisional groupings from one session and should be confirmed against further observation before the register is extended.

### 3.2 Task coverage was narrow

Of the 31 register tasks, roughly seven were observed: 1, 2–3, 8–9, 17, 23, 26, 28.

Not observed at all in this session: pre-PO price control (14–16), Exact `Advies` / `Toewijzen` (12–13), authorization and approval routing (18–21), historical PO investigation (5), hold/pause (11), Finance-returned rework (29–30).

**Both price-control episodes were post-confirmation (Task 26). No pre-PO price check (Tasks 14–16) occurred during the session.**

### 3.3 Case fragmentation

OBS-14/15 consumed approximately **23–28 minutes of recorded work across 53 minutes of clock time**, in seven segments, interrupted by calls, a missing drawing, colleague contact and a visit to Engineering. The range depends on the open question in §4.

## 4. Open questions before the baseline

1. **Interrupting-call attribution.** For 11:23–11:29, are the recorded minutes active work on the OBS-14/15 PO, or time spent on the interrupting calls? If the latter, they belong in `INT` and to their own case, and OBS-14/15's active time falls to ≈23 minutes. This affects both the active-time figures and the interruption rate.
2. **OBS-01/09 maximalisatie.** Was demand actually combined (Task 10), or only searched and assessed (8–9)?
3. **OBS-16, 11:38–11:40.** Purchasing entry from a request (2–3) or completion of the supplier PO (17)?
4. **11:50–11:57.** Seven minutes with no recorded episode; reason not established.
5. **Register extension.** Should the four activity types in §3.1 be added as register tasks before the baseline, or recorded under a temporary `OTHER` code and grouped during Analyze?

## 5. Method observations from the pilot

- Case identity failed twice in fifteen cases (`OBS-01`/`OBS-09`, `OBS-14`/`OBS-15`). The sheet needs a running index of open cases so a returning case can be looked up rather than renumbered.
- No `MISS` was logged, although the raw notes marked one skipped observation. The MISS rate is a pilot criterion in the protocol and needs to be recorded rather than dropped.
- Uncertain observations (OBS-03 outcome, OBS-08) were already unrecoverable within one day. Task-ID coding and note completion should follow the session immediately.
- The example row written on the sheet was nearly recorded as a real observation. Example rows should not appear on live sheets.
- Coverage is one morning of one buyer. Task frequencies from this session are not representative and are not used as baseline estimates.
