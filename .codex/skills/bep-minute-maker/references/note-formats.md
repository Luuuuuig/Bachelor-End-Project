# Note formats

Choose the smallest structure that preserves the source. Do not force observation notes into meeting-minutes headings.

## Formal meeting minutes

Use these exact sections when the user asks for meeting minutes or supplies this format:

1. **Meeting Overview**: Date, time, attendees, meeting type, and purpose, when stated.
2. **Executive Summary**: Up to three sentences covering the meeting's main goal and confirmed outcome.
3. **Key Discussion Points**: Grouped by topic or agenda item.
4. **Decisions Made**: Only explicit agreements or confirmed choices.
5. **Action Items**: For each item, state Task, Owner (Who), and Deadline (When).
6. **Next Meeting**: Date and time, when stated.

Write `None noted` when a required section has no supported information.

## Internship or observation note

Use a dated descriptive title, a short scope statement, and topic-based sections that follow the observed work. A useful structure can include:

- context and people involved;
- observed workflow;
- systems, documents, labels, or status codes used;
- exceptions and edge cases;
- statements or explanations supplied by staff;
- decisions and actions, only when present;
- unresolved questions.

Keep direct observation distinct from what a participant explained. Preserve timing as observed elapsed time or active handling time according to the source. Do not generalize one observed case into a typical duration or universal process.

When the source is a structured observation sheet:

- preserve its row order, case IDs, activity codes, timestamps, quantities, interruption fields, decision indicators, and notes;
- leave a Note cell blank when the source Note cell is blank;
- do not move nearby commentary into a row unless the user confirms that it belongs to that row;
- keep separate comments below the table when their row association is uncertain;
- retain resumed or interrupted activities as separate records when the source does so;
- label a duration as elapsed time when interruptions prevent a defensible active-handling duration.

## Raw handwritten notes

Transcribe legible content first. Mark unreadable or ambiguous fragments and ask the user to resolve them before finalizing. Do not guess abbreviations or reconstruct missing words from context when the guess would change the record. If the user wants an immediate provisional transcription, use `[unclear]` for unresolved text and state that the note is not final.
